# Lot 1 · Entrée du parcours : plan d'implémentation

> **Pour les agents :** sous-skill requis : superpowers:executing-plans. Étapes en cases `- [ ]`.

**Objectif :** du QR code à la première fournée : landing, plateforme grisée, questionnaire, restitution, faux e-mail de confirmation, création du mot de passe, connexion, mot de passe oublié, confidentialité, pages protégées. Tout simulé dans le navigateur.

**Architecture :** logique d'authentification pure et testée dans `auth.js` (adaptateur du futur Supabase Auth), règles du questionnaire dans `questionnaire.js`, garde des pages dans `garde.js`. Écrans du parcours = une page HTML chacun sur le modèle existant (`dc.js` + `boot.js`), avec une feuille de style partagée `parcours.css` pour les cartes, champs, boutons et la barre de progression.

**Stack :** HTML/CSS/JS sans build, ES5 dans le site, `node --test "tests/*.test.js"`.

**Spec :** `docs/superpowers/specs/2026-11-17-lot1-entree-design.md` (et la feuille de route `2026-11-17-front-roadmap-design.md`).

## Contraintes globales

- Aucun appel réseau, aucun vrai e-mail, aucun Tally : tout en `localStorage`. **Aucun mot de passe n'est jamais stocké**, nulle part.
- Clés : `pq-auth` (comptes, session, demande en cours), `pq-questionnaire` (brouillon). Les deux s'ajoutent à `Store.CLES_DEMO`.
- Compte de démo toujours présent : prénom `Léa`, e-mail `lea@demo.painquotidien.fr`, statut `actif`, profil : métiers `["Consultant"]`, thématiques `["Automatisation et agents", "IA en entreprise", "LLMs"]`, relation `En couple`, langue `Je veux des sources françaises uniquement`.
- Règles du mot de passe : 8 caractères minimum, au moins une majuscule, au moins un chiffre.
- Textes des choix du questionnaire = ceux du Tally, mot pour mot (voir la spec).
- Tutoiement, FR/EN, 44 px, focus visibles, aucune impasse : chaque écran a une suite et un retour.
- Une mention discrète « Démo : aucun e-mail ni mot de passe n'est réellement envoyé ou enregistré » sur les écrans de compte.
- Branche `feat/lot1-entree`, commits locaux signés `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Points de vigilance

1. Redirection ouverte : `/connexion?retour=//site-pirate.fr` ou `retour=https://…` ne doit jamais sortir du site. Testé en tâche 2 (`retourSur`).
2. Recharger `/creer-mot-de-passe` sans demande en cours (lien ouvert directement) : message « ce lien n'est plus valable » + lien vers la connexion, pas de création de compte fantôme. Testé en tâche 1, vérifié en tâche 5.
3. S'inscrire avec l'e-mail d'un compte déjà actif (dont celui de Léa) : message « un compte existe déjà, connecte-toi », sans écraser le compte. Testé en tâche 1.
4. Mot de passe oublié avec un e-mail inconnu : même message que pour un e-mail connu (on ne révèle pas quels comptes existent). Testé en tâche 1.
5. Recharger le questionnaire au milieu : on retrouve l'étape et les réponses. Testé en tâche 4 (brouillon) et vérifié dans le navigateur.

### Tâche 1 : adaptateur `auth.js`

**Fichiers :** créer `auth.js`, `tests/auth.test.js` ; modifier `store.js` (`CLES_DEMO`), `tests/store.test.js`.

**Interfaces produites** (`window.Auth` / `module.exports`) :
- Constantes : `CLE = 'pq-auth'`, `COMPTE_DEMO` (voir contraintes, avec `abonneId: 'demoLea0000000001'`, `inscritLe: '2026-10-01T08:00:00.000Z'`, `activeLe` identique).
- `etatInitial()` : `{ version: 1, comptes: [COMPTE_DEMO], session: null, demande: null }` ; `normaliser(raw)` (version différente ou forme invalide : état initial ; le compte de démo est toujours remis s'il manque).
- `emailValide(email): boolean` (forme `x@y.z`, sans espace) ; `reglesMotDePasse(mdp): { longueur, majuscule, chiffre, ok }`.
- `genererIdentifiant(aleatoire: () => number): string` : 16 caractères parmi `A-Za-z0-9` (dans le navigateur, `aleatoire` s'appuie sur `crypto.getRandomValues`).
- Fonctions pures, chacune renvoie `{ etat, erreur }` (`erreur` vaut `null` en cas de succès) :
  - `inscrire(etat, profil, maintenantIso, identifiant)` ; `profil = { prenom, email, metiers, thematiques, relation, langue }`. Erreurs : `email-invalide`, `email-existant` (compte `actif` avec cet e-mail, insensible à la casse). Un compte `a-confirmer` au même e-mail est remplacé. Pose `demande = { email, motif: 'inscription' }`.
  - `definirMotDePasse(etat, mdp, maintenantIso)`. Erreurs : `aucune-demande`, `mot-de-passe-faible`. Succès : compte `actif`, `activeLe` posé s'il était absent, `session = { email, depuis }`, `demande = null`.
  - `seConnecter(etat, email, mdp, maintenantIso)`. Erreur unique `identifiants` (e-mail inconnu, compte non actif, ou mot de passe hors règles).
  - `motDePasseOublie(etat, email)` : jamais d'erreur ; pose `demande = { email, motif: 'reinitialisation' }` seulement si un compte actif existe.
  - `seDeconnecter(etat)`.
- Lecture : `utilisateurCourant(etat)` : compte de la session ou `null` ; `demandeEnCours(etat)` : `demande` ou `null` ; `fourneeAuFour(etat, maintenantIso)` : `true` si le compte connecté a `activeLe` à moins de 4 000 ms de `maintenantIso`.
- Enveloppe navigateur : `Auth.charger()` / `Auth.enregistrer(etat)` sur `localStorage` (dans un `try`), et les six méthodes de la feuille de route qui chargent, appliquent, enregistrent : `inscrireDepuisQuestionnaire(profil)`, `definirMotDePasse(mdp)`, `seConnecter(email, mdp)`, `motDePasseOublie(email)`, `seDeconnecter()`, `utilisateurCourant()`. Elles renvoient `{ ok: boolean, erreur }`.

### Tâche 4 : questionnaire
